# Mobile apps (iOS and Android)

There are two ways to ship the game as an app. Both stay in the repository:

|                 | `apps/native` — React Native                             | `apps/mobile` — Capacitor             |
| --------------- | -------------------------------------------------------- | ------------------------------------- |
| UI              | Native views (React Native), battlefield drawn with Skia | The web client inside a WebView       |
| Projects        | One Expo project; `ios/` and `android/` are generated    | Checked-in Xcode and Android projects |
| Shared with web | `client-core`: sessions, flow, renderer, sound mapping   | Everything (it is the web client)     |
| Extra UI code   | Its own screens (`apps/native/src`)                      | None                                  |

## React Native app (`apps/native`)

Expo SDK 54 / React Native 0.81 with the new architecture. SDK 54 is the newest release that
builds with Xcode 16; SDK 55 and later need Xcode 26 (Swift 6.2). Upgrade with
`npx expo install expo@latest --fix` once Xcode is updated. It has no game logic of its own:

```
packages/client-core  ──►  apps/native/src
  sessions, flow, hooks        screens/   menu, setup, online lobby and room
  BattleStage, SceneRenderer   battle/    shop, battlefield (Skia), controls, overlays
  sound mapping                platform/  Skia Canvas2D adapter, AsyncStorage cache, expo-audio
```

- **Battlefield.** `platform/skia-canvas.ts` implements the `Canvas2D` interface on a Skia
  canvas, so the shared painters draw the same picture as in the browser. Cached layers are Skia
  pictures (`picture-layer.ts`). `Battlefield.tsx` records one picture per frame.
- **Assets.** Sounds and weapon icons are the web client's files (`apps/client/public`),
  bundled through `platform/sound-assets.ts` and `platform/weapon-icons.ts`. A new sound or
  weapon needs a line there (the `Record<EffectId, …>` type makes the compiler remind you).
- **Sound.** `platform/expo-audio-service.ts` plays the same music and effects as the web.
  It follows the iPhone's ring/silent switch (`playsInSilentMode: false`), as games usually do:
  with the switch on silent the game makes no sound. Music pauses while the app is in the
  background.
- **Storage.** `platform/storage.ts` loads AsyncStorage into memory at launch, because the
  shared stores are synchronous. Seat token, sound switches and the last profile live there.
- **Server address.** `EXPO_PUBLIC_SERVER_URL` in `apps/native/.env` (default
  `http://localhost:5001`, which only works in the iOS simulator; the Android emulator needs
  `http://10.0.2.2:5001`, a device needs the LAN or public address).

```bash
npm run native:ios        # builds packages, generates ios/, builds and opens the simulator
npm run native:android    # same for Android (needs Android Studio + an emulator or device)
```

The first build installs CocoaPods dependencies and compiles React Native, which takes several
minutes. CocoaPods must be installed (`brew install cocoapods`) and needs a UTF-8 locale:
run `export LANG=en_US.UTF-8` first if `pod install` fails with an encoding error. `ios/` and `android/` are generated by `expo prebuild` and are not committed; native
settings belong in `app.json`.

The web client uses a newer React (19.2) than React Native 0.81 allows (19.1), so the
workspace holds two copies: the root one for the native app and a nested one for
`apps/client`. Vite dedupes React for the web bundle (`resolve.dedupe`).

Verified on the iOS simulator and an Android emulator (menu, setup, battle, shots). Online
play has not been tried on a device yet.

Android needs a JDK and the SDK location; Android Studio's bundled JDK works:

```bash
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
export ANDROID_HOME="$HOME/Library/Android/sdk"
```

The first Android build downloads the NDK (about 1 GB) and compiles Skia, which takes around
ten minutes. On a slow emulator the battlefield can take a few seconds to appear.

## Capacitor shells (`apps/mobile`)

The mobile apps are **Capacitor shells** around the web client: `apps/mobile` contains the
native Xcode and Android Studio projects, which load the built `apps/client/dist`. There is no
second implementation of the game — engine, UI and audio are the same code as on the web.

```
apps/client   ──build──►  dist/  ──cap sync──►  apps/mobile/ios      (Xcode project, SPM)
                                           └─►  apps/mobile/android  (Gradle project)
```

## Three ways to play on a phone

|                | How                                         | Notes                                                                                         |
| -------------- | ------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Mobile website | Open the URL                                | Touch layout for both orientations; fullscreen button where the browser allows it (Android)   |
| Installed PWA  | Browser menu → Add to Home Screen / Install | Full screen, landscape (`manifest.webmanifest`), offline play for local modes, music included |
| Store apps     | `apps/native` or `apps/mobile`              | See above and below                                                                           |

The service worker (`vite-plugin-pwa`, registered in `shared/register-service-worker.ts`) is
skipped inside the native apps. Web icons come from the shared logo:
`npm run icons -w @tank-tussle/client`.

## What is mobile-specific

| Where                              | What                                                                                                                                                                                                                                                                                                                |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `apps/client` `CompactBattle`      | Landscape phone layout: battlefield in the middle, angle + move under the left thumb, power + fire under the right, weapon picker in the top bar. Chosen by the `PHONE_SCREEN` media query, so it also applies to phones in the browser; upright phones get the field on top and the two panels side by side below. |
| `apps/client` `shared/platform.ts` | `isNativeApp()` (detects the shell through `window.Capacitor`, no native dependency), no pinch-zoom / text selection in the app, public URL for invite links.                                                                                                                                                       |
| `apps/client` CSS                  | `env(safe-area-inset-*)` paddings for notches, `viewport-fit=cover`, bundled fonts (no network needed).                                                                                                                                                                                                             |
| `apps/client` audio                | Music and effects stop while the app is in the background.                                                                                                                                                                                                                                                          |
| `apps/client` credentials          | The seat token is kept in `localStorage` in the app, so a match can be resumed after the app was closed.                                                                                                                                                                                                            |
| `apps/mobile/ios`                  | Landscape only, status bar hidden, local-network HTTP allowed (`NSAllowsLocalNetworking`) for development.                                                                                                                                                                                                          |
| `apps/mobile/android`              | `sensorLandscape`, immersive full screen (`MainActivity`), cleartext HTTP in **debug** builds only.                                                                                                                                                                                                                 |

## Rendering pitfalls

- **No `shadowBlur` on the battlefield canvas.** In Android WebView, canvas shadows combined
  with gradients in the same frame erased earlier `drawImage()` output — the whole sky turned
  transparent. Glows are radial-gradient halos (`drawHalo`); ESLint rejects `shadowBlur`.

## Requirements

- iOS: macOS with Xcode 16+. Dependencies come through Swift Package Manager (no CocoaPods).
- Android: Android Studio (SDK 36). Its bundled JDK is enough; from a terminal set
  `JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"`.

## Build and run

Environment variables are compiled into the web build, so set them when syncing:

| Variable          | Purpose                                                                                      |
| ----------------- | -------------------------------------------------------------------------------------------- |
| `VITE_SERVER_URL` | Game server for online play. Must be reachable from the phone (your deployed Render URL).    |
| `VITE_PUBLIC_URL` | Public website (Netlify) used for invite links. Without it the app hides "Copy invite link". |

```bash
VITE_SERVER_URL=https://tank-tussle-server.onrender.com VITE_PUBLIC_URL=https://tank-tussle.netlify.app npm run mobile:sync
```

```bash
npm run ios -w @tank-tussle/mobile        # opens Xcode: pick a simulator or device, press Run
```

```bash
npm run android -w @tank-tussle/mobile    # opens Android Studio: pick an emulator or device, press Run
```

`npm run mobile:sync` = build shared packages → build the client → copy it into both native
projects. Run it again after every change to the web code.

### Using a game server on your computer

| Target                       | `VITE_SERVER_URL`                  | Extra                                                                                                           |
| ---------------------------- | ---------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| iOS simulator                | `http://localhost:5001`            | —                                                                                                               |
| Android emulator             | `http://10.0.2.2:5001`             | also set `TANK_TUSSLE_LOCAL_SERVER=1` when syncing (allows HTTP from the app's HTTPS origin; debug builds only) |
| Real phone on the same Wi-Fi | `http://<your computer's IP>:5001` | Android: as above                                                                                               |

Offline modes (CPU, two players, practice) need no server at all.

### Server CORS

The apps load from `capacitor://localhost` (iOS) and `https://localhost` (Android). If
`CORS_ORIGIN` on the server is restricted, add both origins next to the website's.

## App icon and splash screen

`apps/mobile/assets/logo.svg` is the source. `npm run assets -w @tank-tussle/mobile` renders it
and regenerates every icon and splash size for both platforms.

## Before publishing to the stores

- **App id**: `com.gokhankaraoglu.tanktussle` in `capacitor.config.ts`, the Xcode project and
  `android/app/build.gradle`. Change it everywhere before the first upload; it cannot change later.
- **Signing**: an Apple Developer account + signing team in Xcode; an upload keystore for Google Play.
- **Name and assets**: the game is called Tank Tussle and its logo (`apps/mobile/assets/logo.svg`),
  weapon names, icons, sound effects and music are original. Check that the name is still free
  in the stores and trademark registers before the first upload.
- Bump `PROTOCOL_VERSION` discipline matters more on mobile: old app versions stay installed, so
  the server will refuse them after a protocol change until they update.
